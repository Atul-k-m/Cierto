# ADR-003: Rules-first detection, workflow-first support, agent only for exceptions

**Status:** Proposed
**Date:** 2026-09-29
**Deciders:** Ishrajesh (owner)

## Context

- No labelled failure data exists; the 93 complaints are a catalogue of failure modes, not a training set.
- Vendors' "AI" deflection claims (60–80%) are unaudited; real WISMO automation in public case studies is 26–56% (Gorgias). Klarna re-hired human support in 2025 after cutting too deep.
- Swiggy already runs an enterprise multi-agent support system, and users still describe bot loops. Another chatbot is not the wedge; **what the bot knows and is allowed to do** is.
- Anthropic's guidance: deterministic workflows for predictable paths, agents for open-ended ones. Shopify's Sidekick: keep one agent under ~20 tools; return just-in-time instructions with tool results; validate the LLM judge against human labels.
- Hinglish measurably degrades model accuracy and appears in the corpus ("10 bar ek issue raised kar chuki hai").

## Decision

**Detection: transparent rules plus one statistical check, no ML in the proof of concept.**
- Per-vertical rule profiles (parcel: hours/days; quick commerce: minutes) over the order projection. Examples: delivered-without-proof, delivered before ETA, ETA revised ≥ 2 times, no scan for N hours, out-for-delivery > 24h, partner search > N min, rider stationary at pickup > N min, refund initiated > 7 working days with no bank reference, payment captured with no order after N min, AWB phone ≠ account phone, contacts per order ≥ 2 in 7 days, case closed while exception live.
- **Incident detector:** rate of unverified deliveries per courier × pincode × day against a rolling baseline. This is the December 2025 replay.

**Support: three tiers.**
1. **Router** (small model, structured output): intent, language register (en / hi-Latn / hi-Deva / mixed), urgency, order reference.
2. **Workflow answers** for status questions: templated from the projection, no LLM authoring facts. Dates, amounts and IDs are never generated by a model.
3. **Exception agent** (Claude via the client SDK tool runner) only for open cases: not received, failed delivery, refund stuck, wrong or missing item. At most ~10 tools, each returning a readable narrative plus the policy text relevant to that state:
   `order.lookup`, `shipment.timeline`, `policy.search`, `delivery.request_reattempt`, `delivery.defer`, `consignee.update`, `case.open_or_update`, `customer.notify`, `refund.propose` (human approval), `reship.propose` (human approval).

**Guardrails (enforced in code, not prompts):**
- Money-moving tools create an `ApprovalRequest` (action, amount, evidence bundle, proposer, expiry) with tenant thresholds; a human approves in the support console.
- A case cannot close while its order has a live exception; closure needs a state change or customer confirmation.
- "Talk to a person" is always offered and never gated behind re-answering questions.
- Strict tool schemas so the agent cannot invent AWB numbers or refund amounts; every action lands in an append-only audit log.

**Models:** router and judge on a small, fast tier; exception agent on the strongest tier. Chosen by a small A/B on Hinglish-heavy seed cases, not assumed.

## Options considered

| | Chatbot on a tracking API | ML anomaly models | **Rules + workflow + narrow agent (chosen)** |
|---|---|---|---|
| Needs labelled data | No | Yes (none exists) | No |
| Explainable to a customer | Low | Low | High: every flag has a named rule |
| Risk of wrong money moves | High | n/a | Low: human approval |
| LLM cost | High (every message) | n/a | Low: LLM only on exceptions |
| Demo credibility | Low (everyone has one) | Medium | High, measured on the replayed corpus |

## Evaluation

A small "tau-bench for WISMO": simulated users generated from real complaint texts (≥ 20% Hinglish), seeded orders, per-tenant policy. Report **pass^3** (all of three runs succeed), not pass^1. Procedural checks first (schema validity, forbidden actions, closure rules, never re-asking the order ID); an LLM judge only after ~100 conversations are human-labelled and agreement is measured.

## Consequences

- **Easier:** every alert is explainable; LLM spend scales with exceptions, not orders; the pitch reports honest, separated metrics (automation rate vs verified resolution rate).
- **Harder:** rule thresholds need tuning per vertical; the rules list must stay curated.
- **Revisit:** a per-tenant breach classifier once real event history accumulates (Phase 5+).
